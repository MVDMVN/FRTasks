# Статистика

**Уровни:**

1. узнаю
2. повторю по образцу
3. **применю в новой ситуации и знаю, когда не надо**
4. объясню другому и назову компромиссы

**Цель — третий.** Четвёртый — для ключевых тем и всего, что спросят на
собеседовании.

**Правило:** уровень 3 засчитывается, только если написал рабочий код без
подсказок. Не «понял объяснение», не «тесты зелёные с четвёртой попытки после
трёх наводящих вопросов».

Смягчение портит измерение. Решил с подсказками — так и записываем.

## Как читать эти цифры

**Низкий уровень сразу после чтения — нормально.** Это найденные дыры, пока
они дешёвые.

Плохо другое:

- **При перепроверке хуже, чем было сразу после чтения.** Дыру не закрыли
- **Уровень застрял на 2 после второй проверки.** Узнаёт материал, но не
  применяет. Лечится задачами, а не перечитыванием
- **Тесты зелёные, но уровень 2.** Самая опасная ловушка — ощущается как
  понимание. Именно так прошла тема 2.4

## История по темам

### Промисы / async-await — два неудачных захода

**Заход 1 (задача `retry`).** Комбо из трёх новых идей разом: промисификация
`setTimeout`, `throw` vs `return` для отклонения промиса, границы цикла
попыток. Сгорел, решение в итоге вставил наставник, ученик скопировал.

**Заход 2 (теория с нуля).** Разбирали механику: однопоточность → колбэк →
промис как объект-контейнер «значение, которого ещё нет». Дошли до
`Promise { <pending> }`, на вопросе «почему pending, а не готовое значение»
попросил остановиться.

**Вывод:** тему брать только маленькими изолированными шагами и только когда
сам скажет. Первый шаг заготовлен и не начат: обернуть `setTimeout` в промис,
без `throw/catch` и без циклов. По плану Кантора тема придёт в главе 10.

### Уроки по механике языка, которые уже разобраны

- `reduce` без `initialValue` берёт первый элемент массива как стартовый `acc`
- колбэк с блочным телом без явного `return` возвращает `undefined` — и это
  `undefined` остаётся элементом массива после `map`, массив не укорачивается
- `setTimeout(fn(...args))` — это немедленный вызов, в таймер уходит результат;
  нужна обёртка `() => fn(...args)`
- `{ ...item, done: true }` — не магия spread, а обычное правило литерала
  объекта: последний одноимённый ключ побеждает
- `Object.groupBy` возвращает объект **без прототипа**, из-за чего строгое
  сравнение с обычным `{}` падает
- в `async`-функции `return err` резолвит промис, отклоняет только `throw`

### Повторяющиеся ошибки (модель, а не случайность)

- **Отладочные `console.log` остаются в решении** — 4 раза. К теме 2.9 начал
  убирать сам
- **Костыль вместо пересмотра логики** — вместо разбора порядка веток
  подгонял границу (`<= 89.9`). Чутьё при этом верное: сам назвал костылём
- **Лишние промежуточные переменные** — `const result = Boolean(value);
  return result`
