ЗАДАЧА 2.10-1 — GRADE LABEL (ветвление + всё пройденное)


О ЧЁМ ЗАДАЧА

Первая задача "по нарастающей": тут собирается вместе всё, что ты уже
прошёл — переменные (2.4), преобразование типов (2.7), сравнения (2.9)
и условное ветвление (2.10).

Студент ввёл балл за экзамен (строкой, как всегда с ввода). Надо выдать
словесную оценку.


ЧТО ИМЕННО ПИСАТЬ

Файл solution.js:

    export function getGradeLabel(input) { ... }

input — строка с баллом.

Шкала:

    90 и больше       -> 'отлично'
    от 70 до 89       -> 'хорошо'
    от 50 до 69       -> 'удовлетворительно'
    меньше 50         -> 'неудовлетворительно'

Если ввод некорректный — вернуть null. Некорректный это:
    - пустая строка
    - не число вообще ('abc', '80баллов')
    - число меньше 0
    - число больше 100


ПРИМЕР

    getGradeLabel('95')      // 'отлично'
    getGradeLabel('90')      // 'отлично'          граница
    getGradeLabel('89')      // 'хорошо'           граница
    getGradeLabel('70')      // 'хорошо'           граница
    getGradeLabel('50')      // 'удовлетворительно'
    getGradeLabel('49')      // 'неудовлетворительно'
    getGradeLabel('0')       // 'неудовлетворительно'
    getGradeLabel('  85  ')  // 'хорошо'           пробелы не мешают

    getGradeLabel('')        // null
    getGradeLabel('abc')     // null
    getGradeLabel('-1')      // null
    getGradeLabel('101')     // null


НА ЧТО ОБРАТИТЬ ВНИМАНИЕ

1. Границы. Самая частая ошибка в таких задачах — перепутать > и >=
   и сломаться ровно на 90, 70 или 50. Тесты проверяют каждую границу
   с обеих сторон, так что если где-то ошибёшься на единицу — увидишь.

2. Сначала разбираешься с некорректным вводом, потом со шкалой. Если
   всё смешать в одну кучу, будет каша из вложенных if.

3. Порядок проверок в шкале имеет значение. Подумай, почему если начать
   проверки с "меньше 50", логика получится другая, чем если начать
   с "90 и больше".


ОГРАНИЧЕНИЕ

Логические операторы (&& || !) — тема 2.11, ещё не пройдена. Диапазон
"от 70 до 89" отдельной проверкой с && писать НЕ НАДО — если правильно
выстроить порядок if-ов, каждая проверка получается одиночной. В этом и
есть смысл пункта 3 выше.

Массивов, объектов, циклов и их методов тоже нет.
