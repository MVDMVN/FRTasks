ЗАДАЧА 2 — DEBOUNCE


О ЧЁМ ЗАДАЧА

Классика на замыкания. Есть функция debounce(fn, delay), которая оборачивает
любую функцию fn и возвращает новую функцию.

Смысл: если обёрнутую функцию дёргают часто подряд (например поле поиска при
каждом нажатии клавиши), реальный fn должен вызваться только один раз — через
delay миллисекунд ПОСЛЕ ПОСЛЕДНЕГО вызова. Каждый новый вызов сбрасывает
таймер и переносит срабатывание дальше.


ПРИМЕР (по времени, delay = 300)

    const log = debounce((text) => console.log(text), 300)

    log('a')   // t=0
    log('ab')  // t=100  — сбрасывает таймер от предыдущего вызова
    log('abc') // t=150  — снова сбрасывает

    // ничего не вызвалось в момент t=150 + 300 = 450,
    // потому что таймер сбросили ещё раз в t=150
    // fn вызовется один раз в момент t=450, с аргументом 'abc'

Если бы вызовы были реже, чем delay, — сработал бы каждый:

    log('x')  // t=0    -> fn('x') вызовется в t=300
    log('y')  // t=500  -> fn('y') вызовется в t=800


ЧТО ИМЕННО ПИСАТЬ

Файл solution.js:

    export function debounce(fn, delay) { ... }

Возвращаемая функция должна:
- принимать любые аргументы и передавать их в fn как есть
- при каждом вызове сбрасывать предыдущий таймер (если он ещё не сработал)
- вызывать fn только один раз, через delay мс после последнего вызова


ПОДСКАЗКА ПО ИНСТРУМЕНТАМ (не решение)

setTimeout / clearTimeout. Id таймера и последние аргументы нужно где-то
хранить между вызовами — вот тут и нужно замыкание.


ОГРАНИЧЕНИЕ

Без внешних библиотек (lodash.debounce и т.п.) — весь смысл в том, чтобы
написать руками и понять механику замыкания.


ПРОВЕРКА

Тесты используют встроенные fake-таймеры node:test (t.mock.timers) — реальных
секунд ждать не придётся, тесты быстрые. Зелёные тесты = задача сдана.
